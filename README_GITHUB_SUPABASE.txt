ТОЧКА ОПОРЫ v15.3
GitHub Pages + Supabase · психолог + клиент · тестовый режим

1. ЧТО ЭТО
-----------
Статическое приложение для GitHub Pages с Supabase как общей базой.
Психолог регистрируется/входит по e-mail + пароль.
Клиент не регистрируется: открывает персональную секретную ссылку.

2. ЧТО УЖЕ НАСТРОЕНО В ВАШЕМ SUPABASE
--------------------------------------
Project URL: https://skdgeamuonxtbzljhfzc.supabase.co
Таблица: public.tochka_workspaces
RLS: включён
RPC клиента и психолога: создан ранее через SQL Editor.

3. ЧТО НАДО СДЕЛАТЬ ПЕРЕД GITHUB
--------------------------------
Открыть supabase-config.js и вставить Publishable key.
Никаких npm, Node.js, PowerShell и командной строки не нужно.

4. КАК ЗАГРУЗИТЬ В GITHUB
--------------------------
Через браузер:
- создать новый репозиторий, например tochka-opory;
- Upload files;
- загрузить ВСЕ файлы из этой папки в корень репозитория;
- Settings → Pages;
- Source: Deploy from a branch;
- Branch: main / root;
- Save.

После публикации GitHub выдаст адрес вида:
https://ВАШ-ЛОГИН.github.io/tochka-opory/

5. ПЕРВЫЙ ВХОД ПСИХОЛОГА
-------------------------
На главной странице:
«Первый вход? Создать кабинет психолога» → e-mail → пароль.
Если Supabase потребует подтверждение e-mail, подтвердить письмо,
затем вернуться на сайт и войти.

Каждый приглашённый психолог должен создать СВОЙ аккаунт.
Не давайте ему свой логин и пароль.

6. ТЕСТОВЫЙ РЕЖИМ
------------------
В кабинете психолога есть «🧪 Лаборатория апробации».
Готовые персонажи:
- Замороченная мама
- После расставания
- «Мне просто плохо»
- Молодой человек 23
- Семья после СВО
- После возвращения
- Мама особого ребёнка
- Человек с инвалидностью

Можно создать и собственного тестового персонажа.

В карточке тестового клиента:
- Ссылка клиента
- Открыть как клиент
- Сбросить тест

Рекомендуемая схема собственного теста:
Обычный Chrome = вы как психолог.
Инкогнито / Edge / Firefox / телефон = вы как клиент.

7. КАК РАЗДЕЛЕНЫ ДАННЫЕ
------------------------
client_payload — то, что вводит клиент.
shared_payload — то, что психолог разрешил клиенту видеть.
internal_payload — внутренние записи психолога.

Клиентская RPC-функция не возвращает internal_payload.

8. ПИЛОТНЫЕ ОГРАНИЧЕНИЯ
------------------------
Это версия для апробации продукта, а не сертифицированная медицинская
информационная система. На пилоте используйте псевдонимы и минимум
идентифицирующих/медицинских данных.

9. ЕСЛИ ЧТО-ТО НЕ РАБОТАЕТ
---------------------------
Сначала проверить:
- supabase-config.js содержит sb_publishable_... ключ;
- URL проекта не изменён;
- SQL ранее выполнился с сообщением «ТОЧКА ОПОРЫ: база создана успешно»;
- e-mail психолога подтверждён, если подтверждение включено.
